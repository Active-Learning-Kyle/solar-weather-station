# SYNTHETIC Gate C Example — NOT SITE PERMISSION

> **FICTIONAL TEACHING SCENARIO.** No Innovation Wing/HKU representative provided this response. No site walk occurred. Candidate A/B, observations, restrictions and the conditional decision below are invented for ENGG2202 active-learning discussion. This file cannot authorise installation, satisfy T-079–T-081 or support a claim about a real location.

## Why this example exists

Students can use the scenario to practise turning site constraints into design changes and distinguishing:

- an instructor's preferred location;
- a site role's conditions;
- a project team's engineering response; and
- actual permission and observed evidence.

## Fictional site-staff response

For this teaching scenario, imagine that an Innovation Wing operations representative reviews the pre-walk request and replies:

> We can discuss a short supervised teaching test, but the open outdoor point proposed as Candidate A is not suitable for a first deployment because it is exposed to public circulation, has a larger fall/wind consequence and cannot support the proposed after-hours response. A controlled semi-open point similar to Candidate B may be considered for a temporary 72-hour test, subject to the conditions below. This scenario does not represent an actual Innovation Wing response.

### Fictional conditions

1. **Approval scope:** conditional consideration applies only to the submitted configuration and marked Candidate B zone. Any hardware, footprint, battery, panel, mounting or schedule change requires review.
2. **Temporary mounting:** use a freestanding weighted tripod/base. No drilling, permanent adhesive, railing clamp or attachment to building services/structure.
3. **Configuration envelope:** provide width, depth, total height, mass, centre-of-gravity estimate, solar-panel area/angle, ballast and cable layout before the start decision.
4. **Public separation:** all cables remain inside the footprint; batteries, connectors and electronics remain enclosed; no sharp/pinch/hot surface is accessible. Add a simple boundary/sign if requested during installation.
5. **Test window:** schedule the 72-hour run so installation, daily checks and planned removal occur during confirmed access periods. Students do not receive automatic night/weekend access.
6. **Emergency response:** any student or TA may request an immediate stop. Physical entry/removal follows the approved access route; the instructor retains the decision and named staff route for an after-hours safety concern.
7. **Weather:** do not begin when adverse weather is expected outside the reviewed prototype/mounting envelope. Site staff may require early removal. The exact trigger must be confirmed for a real test; this scenario does not invent HKU policy.
8. **Data/network:** local timestamped logging is mandatory. Wi-Fi is best-effort and remote monitoring is supplementary. Loss of both network visibility and known local-logging state triggers retrieval review.
9. **Inspection:** students complete one physical check daily; TA verifies the record; water ingress, battery distress, abnormal heat/smell or loose mounting triggers immediate stop/isolation.
10. **Information security:** general site photographs/sketches may be used only if permitted. Do not publish exact unattended-device position, access route, contact details or credentials.
11. **Reference instrument:** a handheld temperature/humidity instrument may be available for spot checks in this fictional scenario, but its model/calibration status must be recorded before it is treated as reference evidence.

## Synthetic candidate-site comparison

| Decision area | Candidate A — open outdoor | Candidate B — controlled semi-open |
|---|---|---|
| Outdoor exposure | Stronger sun/rain/wind exposure; closer to the desired full field condition | Partial exposure; still useful for enclosure, logging, power-cycle and workflow learning |
| Public/fall consequence | Higher because of circulation and a less-contained fall zone | Lower because access and fall zone can be controlled |
| Mounting | Ballast and wind-load case not yet justified | Freestanding weighted base appears feasible subject to configuration review |
| Access/response | After-hours retrieval route unresolved | Normal inspection is realistic; staff escalation still required after hours |
| Measurement bias | More open but still affected by buildings | More shelter and local bias; must be stated in the result |
| First-test decision | **Reject for first run** | **Conditionally select for supervised first run** |

## Synthetic Gate C disposition

- **Teaching-scenario decision:** Candidate B — approved with conditions for the fictional exercise.
- **Real-world project status:** **NOT APPROVED; Gate C remains incomplete.**
- **Why Candidate A is rejected:** its stronger exposure does not outweigh the unresolved public/fall, wind-load and access risks for a first test.
- **Why Candidate B is selected:** it offers lower-consequence learning for the first 72-hour integration run even though its weather measurements have more site bias.

## What changes in the design because of the fictional response?

- The first field run becomes a **lower-consequence integration test**, not a full-exposure weather-performance claim.
- Candidate B's shelter/bias becomes an explicit limitation in the report.
- The weighted base, panel wind area, cable containment and configuration envelope become reviewable design outputs.
- Local logging becomes mandatory because site Wi-Fi is not treated as reliable infrastructure.
- Access and retrieval are designed as part of the system rather than administrative afterthoughts.

## Student active-learning prompts

1. Which statements above are fictional site inputs, and which are project-team decisions?
2. Which condition changes hardware, firmware, operations or documentation?
3. Would you accept Candidate B for a first integration run? What evidence would change your decision?
4. What claim about the resulting weather data would be misleading because of the semi-open site?
5. What must be replaced with real evidence before anyone deploys equipment?
