## Change-impact rules

Review the course repository when this project:

- changes its primary stakeholder, deployment context or intended decision;
- reaches a new baseline, prototype, test or release state;
- adds a failure or lesson that should change a course activity/template;
- changes the location or meaning of a linked project-journey page; or
- changes a Green Technology, SDG or ESG claim used by the course.

Review this repository when the course hub:

- changes a stage, template, evidence expectation or terminology;
- changes how the exemplar is presented to students;
- changes the GitHub, AI, safety, sustainability or Teach-to-Learn workflow; or
- changes the expected final repository structure.

Not every review requires edits in both repositories. Record `not affected` in the Pull Request when a paired change is unnecessary.

## Paired-change procedure

1. Link the originating Issue and its counterpart when both repositories are affected.
2. Use focused branches and Pull Requests in each affected repository.
3. Complete the cross-repository checklist in both Pull Requests.
4. Update this table and the course exemplar status after meaningful releases.
5. Merge only after linked claims, paths and statuses are consistent.

The full policy is maintained in the course repository at `docs/exemplar-sync-policy.md`.
