# Core v0.4 — Wind Speed Integration

**Milestone status:** Software integration complete; full-station hardware verification pending.

The verified standalone RS485 wind-speed configuration is promoted into the production pipeline without integrating wind direction.

## Implemented

- SHT4x, BMP180, BH1750, and LTR390 environmental sensing remains active.
- PMS7003 and TEL0157/L76K GNSS remain active.
- Wind speed is acquired through `RS485Manager` with explicit health and recovery.
- Wi-Fi, NTP, HTTP upload, FastAPI, SQLite, dashboard, and history remain active.
- Existing `diag_i2c`, `diag_pms`, `diag_gnss`, `diag_wind_speed`, and `diag_wind_direction` environments remain available.

## Verified protocol boundary

The production driver uses the known-good 4800 8N1, slave 1, function `0x03`, register `0x0000`, one-register, `raw / 10.0 m/s` configuration on GPIO6 RX, GPIO7 TX, and GPIO5 DE/RE. Production changes only the UART peripheral allocation: UART0 is used because USB CDC carries debug output; the standalone diagnostic stays on UART1.

## End-to-end scope

Wind speed flows through `WeatherData`, nullable JSON, FastAPI validation, additive SQLite columns, latest/history APIs, a compact Wind dashboard group, Sensor Status, and the existing line-chart framework. A successful zero reading remains valid. Timeouts produce unavailable/null and do not stop any other subsystem.

## Deferred

- wind direction;
- rain;
- battery telemetry;
- solar telemetry;
- final power optimization.

See [Core v0.4 implementation notes](../core-v0.4.md) for allocation, schema, failure behavior, and the exact hardware test sequence.
